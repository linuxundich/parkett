# Building Parkett

## Requirements

Rust (stable), Meson, gettext, GTK 4.18 or newer, libadwaita 1.8 or newer and VTE for GTK 4
(0.80 or newer).

| Distribution | Packages |
|---|---|
| Arch Linux | `rust meson gettext gtk4 libadwaita vte4` |
| Fedora 44 | `rust cargo meson gettext gtk4-devel libadwaita-devel vte291-gtk4-devel` |
| Ubuntu 26.04 | `rustc cargo meson pkg-config gettext libgtk-4-dev libadwaita-1-dev libvte-2.91-gtk4-dev` |

Debian 13 and Ubuntu 24.04 ship libadwaita and VTE versions that are too old. For the optional
Nautilus menu, install `nautilus-python` (Arch, Fedora) or `python3-nautilus` (Ubuntu).

## Run from the source tree

```sh
cargo run -p parkett
```

`app/build.rs` compiles the GSettings schema and the translations next to the binary, so no
installation is needed. `LANGUAGE=en cargo run -p parkett` starts the English interface on a
German system.

## Install with Meson

Meson installs the binary, the GSettings schema, the `.desktop` file, the AppStream metadata,
the icons and the Nautilus extension:

```sh
meson setup _build --prefix=$HOME/.local --buildtype=release
meson install -C _build
```

Use `--prefix=/usr` and `sudo meson install -C _build` for a system-wide installation.

## Checks

All checks that need no window: formatting, Clippy with warnings as errors, unit tests,
`cargo audit` (known vulnerabilities in dependencies; skipped if
[cargo-audit](https://crates.io/crates/cargo-audit) is not installed), a Meson build and the Meson
tests (`.desktop`, metainfo, GSettings schema, Nautilus extension syntax, `cargo test`):

```sh
build-aux/ci.sh
```

The examples in [USAGE.md](USAGE.md) are parsed by `core/tests/usage.rs`, so the documentation
cannot drift from the file formats.

## Translations

Source texts in the code are English and marked for gettext (`parkett_core::i18n`: `gettext`,
`trf` with named placeholders like `{name}`, `ntrf` for plural forms, `N_` in constants). After
changing texts, run `po/update-pot.sh`: it rebuilds `po/parkett.pot` from the files in
`po/POTFILES.in` and merges it into every `po/*.po`. Then fill in the new entries (`msgfmt
--check po/de.po` finds mistakes). A new language: copy `po/parkett.pot` to `po/<lang>.po`, add
the code to `po/LINGUAS`. The desktop file, the metainfo and the GSettings schema are translated
from the same files.

## Tests in a virtual machine

The scripts in `build-aux/vm/` drive a GNOME test VM (GNOME Boxes, libvirt session) over SSH
and QMP. They expect an SSH key `~/.ssh/id_vmtest` and default to a Fedora VM named
`fedora44-wor` on SSH port 2223; set `VM_DOM` and `VM_PORT` for another VM (for example
`VM_DOM=ubuntu26.04 VM_PORT=2222`).

| Script | Purpose |
|---|---|
| `build-aux/vm/deploy.sh` | copy the source tree into the VM, build, install to `~/.local`, start Parkett the way GNOME Shell does |
| `build-aux/vm/smoke.sh` | smoke test over the window's D-Bus actions: split, tabs, close, undo timeout, no orphaned shells, session restore, markup in tab titles, focus after the main menu, journal without errors |
| `build-aux/vm/shot.sh file.png` | screenshot of the VM |
| `build-aux/vm/atspi.py` | AT-SPI queries inside the VM for the smoke test: tab names, focused element, press a button |
| `build-aux/vm/click.py X Y` | mouse click (`CLICKS=2` double click, `BUTTON=right`) |
| `build-aux/qa/` | throughput and memory measurements |

## Design mockups

The HTML mockups from the design phase need a local web server (ES modules do not load from
`file://`):

```sh
python3 -m http.server 8751 --bind 127.0.0.1 --directory mockups
```

Then open `http://127.0.0.1:8751/`. Every concept page has switches for view, light/dark and
annotations; the state is kept in the URL, for example
`concept-a.html#view=split&theme=dark&hints=0`. The mockups show the German interface.

| File | Content |
|---|---|
| `mockups/index.html` | overview and comparison |
| `mockups/concept-{a,b,c}.html` | the three concepts with five views each |
| `mockups/combined.html` | concept A+ (the chosen combination) with eleven views |
| `mockups/shared/base.css` | libadwaita 1.10 colors and building blocks |
| `mockups/shared/content.js` | shared sample content, split renderer |
| `mockups/shared/icons.css` | Adwaita symbolic icons (CC-BY-SA 3.0 / LGPL-3.0) as masks |

## Icon

The app icon and the symbolic icon live in `data/icons/hicolor/`. They are generated by
[`icon/gen_icon.py`](../icon/gen_icon.py) (a herringbone parquet floor with an inlaid terminal
pane); change the script, not the SVG. Earlier drafts are in `icon/entwuerfe/`.
